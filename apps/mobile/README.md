# Hypha for Android



Flutter provides the interface; Kotlin owns the Android radio/lifecycle integration,

and an ARM64 Rust JNI library supplies the native protocol/cryptographic surface.

See the [project README](../../README.md) for capability status and architecture.



## Prerequisites



- Flutter with a Dart version satisfying `sdk: ^3.12.2` in `pubspec.yaml`.

- An Android SDK and JDK supported by the checked-in Android Gradle plugin and wrapper.

  `android/settings.gradle.kts` pins AGP 9.0.1; the wrapper pins Gradle 9.1.0.

- An ARM64 Android target for the checked-in `arm64-v8a/librelay_jni.so`.

- Rust and a matching Android NDK only when rebuilding the native bridge.



The tracked native library supports ARM64. An x86 emulator requires a separate

native build and packaging entry; Flutter compilation alone does not supply it.



## Build and check



From this directory:



```sh

flutter pub get

flutter analyze

flutter test

flutter build apk --debug --target-platform android-arm64

```



Output: `build/app/outputs/flutter-apk/app-debug.apk` relative to this directory.

Flutter generates local SDK configuration in `android/local.properties`; do not

commit machine paths or signing credentials. The current release build type also

uses the debug signing configuration, so it is not a production signing setup.



For Kotlin/Robolectric tests, first run `flutter pub get`, then:



```sh

cd android

./gradlew :app:testDebugUnitTest

```



On Windows, use `./gradlew.bat`. A focused store run is:



```powershell

.\gradlew.bat --no-daemon --console=plain '-Dorg.gradle.jvmargs=-Xmx2g' `

  :app:testDebugUnitTest --tests '*RelayMeshStoreReliabilityTest'

```



Use `--offline` only after required Gradle/Flutter dependencies are cached.

Open audit probes are invocation-specific; see [the audit guide](../../tools/audit/README.md).

The ordinary test suite excludes those deliberately failing probes.



## Rebuild the native bridge



The library is built from `crates/relay-jni`, not generated by Flutter. From the

repository root, add `aarch64-linux-android` to the pinned Rust toolchain and select

the Android NDK used for development. The tested Windows path uses the GNU LLVM

Rust host toolchain and LLVM-MinGW. Set `ANDROID_NDK_HOME` to the installed NDK and

`HYPHA_LLVM_MINGW_BIN` to the LLVM-MinGW `bin` directory first:



```powershell

rustup toolchain install 1.97.1-x86_64-pc-windows-gnullvm --profile minimal

rustup target add aarch64-linux-android --toolchain 1.97.1-x86_64-pc-windows-gnullvm

$env:PATH = $env:HYPHA_LLVM_MINGW_BIN + ';' + $env:PATH

$env:CARGO_TARGET_X86_64_PC_WINDOWS_GNULLVM_LINKER = Join-Path $env:HYPHA_LLVM_MINGW_BIN 'clang.exe'

$env:CARGO_TARGET_AARCH64_LINUX_ANDROID_LINKER = Join-Path $env:ANDROID_NDK_HOME `

  'toolchains\llvm\prebuilt\windows-x86_64\bin\aarch64-linux-android24-clang.cmd'

$nativeRoot = (Get-Location).Path

$env:CARGO_ENCODED_RUSTFLAGS = @(

  "--remap-path-prefix=$nativeRoot=/src/hypha",

  "--remap-path-prefix=$($nativeRoot.Replace('\','/'))=/src/hypha",

  "--remap-path-prefix=$env:USERPROFILE=/home/build",

  "--remap-path-prefix=$($env:USERPROFILE.Replace('\','/'))=/home/build"

) -join [char]31

cargo +1.97.1-x86_64-pc-windows-gnullvm build -p relay-jni --target aarch64-linux-android --release

Copy-Item -LiteralPath 'target\aarch64-linux-android\release\librelay_jni.so' `

  -Destination 'apps\mobile\android\app\src\main\jniLibs\arm64-v8a\librelay_jni.so'

```



Use the corresponding NDK host directory and compiler launcher on Linux/macOS.

Path remapping keeps personal build paths out of the distributed library.

After Kotlin native declarations or Rust exports change, rebuild and repackage

the library, check the JNI surface, and test on a disposable device/profile.

A symbol check or successful APK build does not prove real-device execution.



## Preserve the privacy boundary



Use synthetic contacts/messages for reports. Never commit a phone database,

Keystore export, private key, or identifying screenshot. Keep the current private

engineering evidence separate from a public source export; see

[publication readiness](../../docs/OPEN_SOURCE_READINESS_2026-10-27.md).
